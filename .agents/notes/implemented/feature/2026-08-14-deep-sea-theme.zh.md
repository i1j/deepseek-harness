# Agent Note: 深海暗色调成为一等主题

Status: implemented

[English](2026-08-14-deep-sea-theme.md) | 中文

## 问题

深色模式原本只有一套通用调色板：所有界面共用同一种灰调，界面本身无法编码"一条信息有多重要"。用户要的是一套"深海世界"设计，其基本逻辑是让人能按信息重要程度依次关注应该关注的内容——chrome 沉入黑暗，对话栏成为亮起的阅读区，文字、元信息与强调色形成可见的层级。此前的修复以 conversation 插件注入的硬编码 CSS 覆盖形式存在：既无法持久化、无法在设置中呈现，也会被任何一次包升级覆盖。

## 决策

**Deep Sea 是注册的内置主题。** ui-theme 注册表新增 `deep-sea` 条目——`colorScheme: 'dark'`，构造上仅限暗色——以单一 94 token 别名覆盖层（`deep-sea.ts`）重绘背景、边框、文字、状态、按钮与 shiki 语法调色板。

**可持久化且可选择。** `THEME_PREFERENCES` 与 Host settings schema 扩展 `'deep-sea'`，偏好经既有 settings scope 写入；外观行增加第四个方块（暗海色板 + 生物荧光青微粒）；插件加载前的 boot 脚本像 `dark` 一样把 `deep-sea` 映射为暗色方案。

**主题作用域样式挂在 presenter 镜像上。** ui-layout 的 theme presenter 现在把活动主题 id 镜像为 `body` 上的 `data-ds-theme`，组件样式即可按主题作用域化：对话 markdown 层级（标题沉为钢蓝 `rgb(100,128,168)`、加粗亮为 `rgb(146,180,222)`、行内代码海玻璃青 `rgb(94,192,226)`、h6 保持灰）、对话栏阅读区背景升为 `rgb(28,35,49)`、侧栏文字层级调暗为 `rgb(158,170,196)`。

**亮度编码层级（L0–L4）。** Chrome 沉入暗海（基底 `rgb(10,14,22)`、侧栏 `rgb(9,13,21)`），对话栏是亮起的阅读区，正文是最亮的生物荧光软白，元信息经 secondary/tertiary/caption 逐级降噪，强调色为深海荧光系（青色主色、荧光绿成功、琥珀警告、珊瑚红错误）。

## 曾考虑的替代方案

**由 conversation 插件注入硬编码 CSS 覆盖。** 不采用：那是 PR 之前的补丁形态——无法选择或持久化、游离于主题系统之外，且会被包升级覆盖。

**另建一套调色板系统。** 不采用：ui-theme 注册表已支持 token 层，新机制只会重复既有能力，对用户没有可见增益。

## 后果

亮色模式完全不动——该调色板构造上仅限暗色，选择 Deep Sea 会强制暗色方案，即使亮色用户也会切到暗色。组件级深海样式挂在 presenter 持有的 `data-ds-theme` 属性上，未来的主题无需新管线即可获得同样的作用域接缝。94 token 层是调优调色板的唯一位置；深色下品牌、按钮与状态面采用深海荧光色系。
